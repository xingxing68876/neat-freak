# neat-freak · 洁癖

**A cross-platform end-of-session knowledge sync skill for AI agents.**

会话收尾时,把项目文档(CLAUDE.md / README / docs/)和 agent 记忆跟代码全面对齐——像有洁癖一样。你不用记得"哪些文档该跟着改",说一句「收尾」,它按清单逐层核对,漏一个不行。

```
你:收尾
AI:## 同步完成
    ### 记忆变更
    - 更新:部署记忆(补环境变量改名结论,相对时间转绝对日期)
    - 删除:xxx迁移待办(已完成)
    ### 文档变更
    - price-radar/CLAUDE.md — 环境变量表补 WATCH_INTERVAL
    - price-radar/docs/integration-guide.md — 新增 /watch 路由说明
    ### 未处理
    - 无
```

## 为什么需要它

AI 协作开发里,**代码可以随时重写,但文档和记忆是跨会话、跨 Agent 的唯一桥梁**。这根桥梁最常见的断法有两种:

1. **漏改**:加了个 API,CLAUDE.md 改了,docs/integration-guide.md 忘了——下游同事接不上;
2. **膨胀**:每次收尾都在 CLAUDE.md 顶部追加一段"X 功能上线,详见 docs/Y.md",半年后 200 行历史叙事把真正的规则挤出 prompt,下次 AI 看不到红线照样踩。

手动收尾要么漏层、要么越写越肥。这个 skill 把收尾变成**有强制清单的仪式**,并且把"防膨胀"放在比"补漏"更高的优先级:

- **三类知识,三种受众**:记忆(给自己)/ CLAUDE.md(给下次的 AI)/ docs(给外部的人)——职责不重叠,两份都要写;
- **规则手册,不是变更日志**:硬性判断标准——"下次 AI 写代码时没看到这条会不会犯错",不会就删/迁走;
- **尺寸体检先行**:CLAUDE.md > 300 行、MEMORY.md > 150 行、单条记忆 > 100 行都触发精简,净涨 30 行即红灯;
- **机械式枚举防漏改**:强制先 `ls` 全部文档再动手,每个文件标「评估过/要改/不用改」,漏一个不算完;
- **变更影响矩阵**:新增 API 改哪几处文档?改环境变量呢?查表执行,不靠脑补;
- **跨项目对齐**:上游 API 变了,下游 SDK 文档必须同步——历次收尾最常翻的车就在这;
- **经验沉淀防蒸发**:收尾不只对文档,还复盘对话本身——复发问题更新旧记忆、高频动作满 3 次提议 skill 化,让经验产生复利。

一句话:**记录员只会往后追加,编辑会审查全局。这个 skill 让你的 agent 当编辑。**

## 安装

**方式一:全局安装(所有项目可用)**

```bash
git clone https://github.com/xingxing68876/neat-freak ~/.claude/skills/neat-freak
```

**方式二:项目级安装(仅当前项目)**

```bash
git clone https://github.com/xingxing68876/neat-freak .claude/skills/neat-freak
```

**方式三:手动**——下载本仓库,把 `neat-freak` 文件夹整个丢进 `~/.claude/skills/`(Windows:`C:\Users\<你>\.claude\skills\`)。

装完重启 Claude Code,输入 `/neat-freak` 验证。

> **其他 agent**:`.codex/skills/`、`.opencode/skills/` 也认这个目录结构;OpenClaw 装 `~/.openclaw/skills/`。路径速查见 [references/agent-paths.md](references/agent-paths.md)。

## 用法

| 你说 | 它做 |
|---|---|
| `/neat-freak` | 跑完整收尾仪式:尺寸体检 → 全量盘点 → 变更同步 → 自检 → 摘要 → 经验沉淀 |
| 「收尾」「定稿」「复盘」「同步一下」「整理文档」 | 同上(skill 自动接,「定稿」会先完成你的主任务再追加仪式) |
| 「更新记忆」「记忆里有条过期了」 | 定向清理记忆层 |
| 「新人能直接上手吗」 | 按 docs 受众标准审一遍对外文档 |

收尾完成它会问一句「本次 1~5 打几分?」——这是唯一必问项,你的分覆盖它的自评分。

## 执行流程(六步)

| 步骤 | 干什么 | 防什么 |
|---|---|---|
| 0. 尺寸体检 | `wc -l` 关键文件,超软限先精简 | 文档膨胀把规则挤出视野 |
| 1. 全量盘点 | 强制 `ls` 所有文档+记忆,逐文件标注 | 漏改(最常翻车点) |
| 2. 变更影响矩阵 | 查表确定每处变更波及哪些文档 | 凭脑补判断漏层 |
| 3. 实际修改 | 真刀真枪 Edit/Write/删,docs → 规则 → 记忆的顺序 | "我打算怎么改"式空转 |
| 4. 自检清单 | 反膨胀 4 条 + 反漏改 11 条逐项过 | 叙事混进规则手册 |
| 5. 变更摘要 | 按"记忆/文档/未处理"汇报 | 黑箱收尾 |
| 6. 经验沉淀 | 复发问题更新旧记忆、高频动作满 3 次提议 skill 化、留痕计数 | 经验蒸发,不产生复利 |

## 好用在哪里

- **不说"应该同步了",直接动手**:skill 明确要求真的用编辑工具改文件,"我会怎么改"的描述不算完成。
- **减法优先**:合并优于追加、删除优于保留、净涨 30 行是红灯——专治"每次收尾都变胖一圈"。
- **受众分层是杀手锏**:大多数文档同步只管 CLAUDE.md;这个 skill 惦记着**下游同事和别的 agent**,docs/ 才是项目知识的最低保障。
- **跨平台**:Claude Code / OpenAI Codex / OpenCode / OpenClaw 通用,记忆路径差异已整理成速查表;没有记忆系统的 agent 自动降级为只同步文档层。
- **唯一需要人介入的场景**:记忆之间出现无法自动判断的矛盾——其他全部自己拍板,不反复打扰你。
- **收尾即复盘**:文档不过期只是一半,经验不蒸发是另一半;满 20 条打分还会主动提议跑统计复盘,整改建议回流规则。

## 适用与不适用

- ✅ 会话/阶段收尾、定稿、周复盘、交接给同事或其他 agent 前
- ✅ 感觉"文档已经跟代码对不上了"的任何时候
- ❌ 纯聊天没有产生新事实?——照样跑一遍审查(过期/冲突/相对时间),审查本身有价值
- ❌ 想要自动改代码?——本 skill 只管知识层,代码是它对齐的依据,不是它的编辑对象
